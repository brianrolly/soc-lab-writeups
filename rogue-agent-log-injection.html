Rogue-Agent Log Injection

An anonymous host on the network enrolled itself into the Wazuh SIEM with no credential, became a trusted agent, and injected a forged security alert — a fake SSH brute-force from an attacker-chosen IP — straight into the SOC's trusted alert stream.

Target wazuh-m · 198.51.100.10 Source caldera-c2 · 198.51.100.20 Date 2026-08-20 Authorized lab · own infrastructure

The mechanism

Crossing the trust boundary

The whole exploit turns on one move: an unauthenticated enrollment converts an untrusted attacker host into a trusted agent. Once across that line, everything the attacker writes is believed.

The kill chain

Seven commands, verbatim

Every command below was run during the exercise; every output is copied from the terminal. Prompts are colored by host — attacker versus SIEM.

01

Recon — find the SIEM's exposed ports

Analysis

Why it worked, and what it costs

The flaw

Wazuh's enrollment service (authd, port 1515) ran with use_password: no and was reachable from a neighboring host.

Enrollment is meant to be a brief, trusted bootstrap. Left open, it is an anonymous grant of a trusted identity.

The impact

Once trusted, the agent controls a telemetry feed. It can forge alerts to bait or exhaust the SOC, or bury real activity under injected noise.

This subverts integrity, not just a host — it attacks the thing that is supposed to see every other attack.

The only tell

The forged event used 203.0.113.66 — an RFC 5737 documentation IP that cannot route. Its blank GeoLocation was the sole giveaway.

A real attacker picks a live IP, and the forged alert becomes indistinguishable from the genuine ones beside it.

MITRE ATT&CK

T1046Network Service Discovery — the recon scan
T1078Valid Accounts — the stolen trusted identity
T1565.001Stored Data Manipulation — the forged record
T1562Impair Defenses — poisoning the SIEM

Response

detect

Built & live. Custom rules now alert on enrollment requests and API brute-force; a re-run of this chain fires them.

prevent

The real fix. Set use_password on authd or close 1515 by default; bind the API to loopback; firewall the SIEM.

harden

Ship alerts off-box to append-only storage so a compromised SIEM cannot rewrite its own history.

Remediation · verified

Found → detected → fixed → re-tested

The entry point was closed at the source. Enrollment now requires a shared secret (use_password: yes + authd.pass), and a new rule fires on agent removal. The identical command from Step 3 was re-run to confirm the fix holds.

root@caldera-c2before · vulnerable
echo "OSSEC A:'ROGUE'" | openssl s_client -connect …:1515 -quiet
OSSEC K:'003 ROGUE-TEST-2 any [redacted]'   ← key handed over
root@caldera-c2after · fixed
echo "OSSEC A:'ROGUE'" | openssl s_client -connect …:1515 -quiet
ERROR: Invalid password. Unable to add agent   ← blocked
resultThe unauthenticated foothold is closed, and the same chain now raises alerts at enrollment (rule 100361) and at removal (rule 100363). Detection proved the risk; configuration removed it.

Authorized exercise. Every action was performed by the lab owner against their own infrastructure, in an isolated home-lab SIEM, to validate detection and drive remediation. No third-party systems were involved. The single forged record has been purged from the index; the evidence export is retained. This document is a defensive purple-team artifact.
